3.2 Proposed Methodology / System Architecture: The high-level blueprint of your system.

The system architecture is defined as follow we have the following fields added upon the echonet lite data frame:
| Field             | Size (Bytes) | Description                                                  |
| ----------------- | ------------ | ------------------------------------------------------------ |
| Version           | 1            | Protocol version for backward compatibility                  |
| Length            | 1            | Total length of the authentication block                     |
| Type of Mechanism | 1            | Identifies authentication type (e.g., HMAC)                  |
| Timestamp         | 4            | Unix timestamp (seconds) for freshness                       |
| Counter           | 4            | Monotonic counter for packet ordering and replay detection   |
| HMAC-n            | 12           | Truncated HMAC (HMAC-96) ensuring authenticity and integrity |
| **Total**         | **23 bytes** | Authentication block size                                    |

a 4-byte counter allows for $2^{32}$ ($4,294,967,296$) packets before resetting. If a smart meter sends 1 packet every second, it would take 136 years to exhaust the counter. This single statistic makes your design look incredibly robust and thoroughly researched.

Adding the forementioned block for authentication helps vendors to easily integrate authentication to echonet lite and also sell distinguish between the products that have a lower level authentication, this provides abstraction and isolation like the authentication mechanism embedded within the device allows it to only respond to the request of the device that is of the same type meaning if there are two devices and both have authentication embedded in them but the mechanism is different for example device 1 has Type of Mechanism (ToM) as 92 (which means SHA-92 Truncated) and device 2 has ToM as 128 (which means SHA-128 Truncated) these both devices could not talk to each other as they both have different authentication mechanism. The version specifies the version of the protocol being use example we call this secured version as version 3, all devices that have different version would not be able to talk to this version. Timestamp is the identify the freshness of a request and also if the request has already been sent as the same. Each device will maintain a request table for itself that will store the request received to the device by this an AI-based algorithm will also be embedded that detects if there is a possibility of an attack or not but this will only be done to the devices that require high voltage or have the capability to handle the algorithm as sensors and other devices don't need such thing it will not be added to it. the counter will be used to monitor how many request are being sent by which device to which device if more than 5 requests are send to one device in 3 seconds that means this is not being sent by a human and that device will suspend request from the other device for 30 seconds. These values will be updated based on real data and latency and other potential concerns will be added as well. Then there is HMAC that will encrypt the authentication message and upon receiving it other other device will decrypt it using the pre-shared key and then the operation/request will be carried out and the response will be generated.
